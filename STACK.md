# Task-менеджер: стек и инструменты

Документ описывает всё, что используется в проекте: фреймворки, библиотеки, сервисы, программы и аккаунты. Требования — в [REQUIREMENTS.md](REQUIREMENTS.md), порядок работ — в [ROADMAP.md](ROADMAP.md).

## 1. Архитектура в двух словах

```
 iPhone (Safari, PWA)  ─┐
 Windows (Chrome/Edge) ─┼──►  Vercel  ──  статический фронтенд (React PWA)
 macOS (Chrome/Safari) ─┘                       │
                                                ▼
                                Supabase: Postgres + Auth + Realtime
                                (правила доступа RLS в базе)
```

- Свой сервер не нужен: фронтенд — статические файлы на Vercel, вся логика данных — в Supabase.
- Права доступа (кто какие заметки видит) проверяются в базе через RLS, а не в коде фронтенда.
- Синхронизация между устройствами и вторым пользователем идёт через Supabase Realtime.

## 3. Бэкенд (Supabase)

| Компонент | Зачем | Требования |
|---|---|---|
| **Postgres** | Хранение заметок, пунктов, ярлыков, участников | все |
| **Row Level Security (RLS)** | «Вижу только свои и общие со мной заметки» | ТР-9 |
| **Auth (Google)** | Вход через Google-аккаунт | ТР-7, ТР-9 |
| **Realtime** (`postgres_changes`) | Мгновенная синхронизация между устройствами и пользователями; учитывает RLS | ТР-7, ТР-9 |
| **SQL-функции (`security definer`)** | Поделиться заметкой по email, сопоставление ярлыков второго участника | ТР-9 |
| **Миграции (Supabase CLI)** | Схема базы хранится в репозитории и воспроизводится | все |

### Модель данных

| Таблица | Основные поля |
|---|---|
| `profiles` | `id` (= `auth.users.id`), `email`, `display_name`, `avatar_url` |
| `notes` | `id`, `owner_id`, `title` (обязательно), `description`, `kind` (`permanent` / `temporary`), `urgency` (`critical` / `urgent` / `not_urgent` / `no_deadline`), `position`, `primary_label_id`, `archived_at`, `created_at`, `updated_at` |
| `checklist_items` | `id`, `note_id`, `text`, `is_done`, `position`, `updated_at` |
| `labels` | `id`, `owner_id`, `name`, `color`; уникальность (`owner_id`, `name`) и (`owner_id`, `color`) |
| `note_labels` | `note_id`, `label_id` |
| `note_members` | `note_id`, `user_id`, `role` (`owner` / `editor`) |

- `urgency` используется только для временных заметок (`kind = temporary`).
- Пункты списка лежат отдельными строками, поэтому одновременные отметки двух людей не затирают друг друга.
- Архив — это заполненное поле `archived_at`; столбец срочности при архивации сохраняется, поэтому восстановленная заметка возвращается на место.

## 4. Хостинг и сервисы

| Сервис | Тариф | Зачем |
|---|---|---|
| **Supabase** | Free | База, вход, Realtime |
| **Vercel** | Hobby (бесплатно) | Хостинг PWA с HTTPS, автодеплой из GitHub, preview-версии для веток |
| **GitHub** | Free | Репозиторий, CI, ежедневные бэкапы через Actions |
| **Google Cloud Console** | Бесплатно | OAuth-клиент для входа через Google |
| Свой домен *(необязательно)* | ~$10–15 в год | Красивый адрес вместо `*.vercel.app` |

### Ограничения бесплатных тарифов

- Supabase Free ставит проект на паузу примерно после 7 дней без запросов; включается кнопкой в панели.
- В Supabase Free нет автоматических бэкапов — делаем свои через GitHub Actions.
- Vercel Hobby — только для некоммерческого использования.
- Лимиты меняются: перед стартом сверить со страницами цен Supabase и Vercel.

## 8. Что не используется и почему

| Не используем | Причина |
|---|---|
| Google Keep API | Работает только в Google Workspace, не умеет редактировать заметки, ярлыки и архив |
| gkeepapi | Неофициальный протокол, может сломаться, нарушает условия использования Google |
| Нативные приложения / App Store | Требуют $99 в год и отдельных сборок; PWA покрывает Windows, macOS и iPhone одним кодом |
| Свой сервер (VPS) | Supabase закрывает базу, вход и синхронизацию |
