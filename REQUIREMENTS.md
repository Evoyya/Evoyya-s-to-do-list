# Task-менеджер: требования

## 1. Контекст

Сейчас задачи ведутся в **Google Keep**. Используются два вида заметок.

### 1.1. Постоянные заметки (закреплённые)

Долгоживущие списки, которые периодически пополняются новыми пунктами. Выполненные пункты зачёркиваются и сворачиваются в блок «N выполнено». Эти заметки редактируются **совместно с девушкой**: каждый со своего аккаунта.

Примеры:

| Заметка | Содержимое |
|---|---|
| Дела по дому | Ремонт колеса; выполнено: запустить стиралку, помыть плиту, пропылесосить… (16 шт.) |
| Магазин | Йогурт, яйца, терияки, пергамент, перец… (84 выполнено) |
| Купить | Фильтры, плинтус, подрозетники, клей плиточный, герметик… (94 выполнено) |

### 1.2. Временные заметки (разовые задачи)

Задачи, которые выполняются один раз в течение недели: дела, связанные с учениками, мелкие бытовые задачи, университетские задания. После выполнения заметка отправляется в архив. Для классификации используются ярлыки (например, «ДЗ», «Срочно», «Яна Англ»).

Примеры:

| Заметка | Тип | Содержимое |
|---|---|---|
| Тестирование Лаб 5 | текст | «До 5 ноября», ярлыки «ДЗ», «Срочно» |
| Яна англ дз | текст | ярлык «Яна Англ» |
| Рекомендательная система | список | Поднять Docker на сервере; проверить защиту персональных данных; 6 выполнено |
| Купить снуп | текст | только заголовок |
| Что нужно купить для Ариши | список + ссылки | Охлаждающий гель, подключить увлажнитель; ссылки на goldapple.ru, ozon.ru |
| Изменения резюме | текст | Первые 2 слайда убрать; опыт передвинуть наверх; о себе в конец |

## 2. Проблема

1. Все временные задачи лежат в одной общей куче, их нельзя упорядочить по **срочности и важности**.
2. Ярлык «Срочно» есть, но он не меняет положение заметки и не даёт наглядной картины, что делать в первую очередь.
3. Хочется, чтобы постоянные заметки жили отдельно (в закрепе), а временные раскладывались по **столбцам срочности** слева направо, как на канбан-доске.

## 3. Термины

| Термин | Значение |
|---|---|
| Постоянная заметка | Долгоживущий список, закреплён вверху, не распределяется по срочности |
| Временная заметка | Разовая задача; после выполнения уходит в архив |
| Столбец срочности | Колонка на доске временных задач: Критично / Срочно / Не срочно / Без дедлайна |
| Ярлык | Пользовательская метка с названием и цветом для классификации задач |
| Общая (парная) заметка | Заметка, доступная двум пользователям на чтение и редактирование |

## 4. Функциональные требования

### ТР-1. Разделение на постоянные и временные задачи

- При создании заметки выбирается её тип: **постоянная** или **временная**.
- Тип можно изменить у существующей заметки.
- Постоянные заметки выводятся отдельным блоком **«Закреплённые»** в верхней части экрана.
- Временные заметки выводятся ниже, на доске со столбцами срочности (см. ТР-2).

**Критерий приёмки:** постоянная заметка никогда не попадает в столбцы срочности, а временная не попадает в блок закреплённых.

### ТР-2. Столбцы срочности для временных задач

- Временные задачи распределяются по четырём столбцам, расположенным **слева направо в порядке убывания срочности**:

  | № | Столбец |
  |---|---|
  | 1 | Критично |
  | 2 | Срочно |
  | 3 | Не срочно |
  | 4 | Без дедлайна |

- Задачу можно перенести между столбцами (перетаскиванием на ноутбуке; перетаскиванием или выбором из меню на телефоне).
- При создании временной задачи можно сразу выбрать столбец; по умолчанию задача попадает в «Без дедлайна».
- Внутри столбца порядок задач можно менять вручную.

**Критерий приёмки:** на экране четыре столбца в указанном порядке; задача после переноса сохраняет новый столбец и на другом устройстве.

### ТР-3. Название и описание

- У каждой заметки есть **обязательное** поле «Название».
- Поле «Описание» **необязательное**: свободный текст (например, «До 5 ноября», «Первые 2 слайда убрать»).

**Критерий приёмки:** заметку без названия сохранить нельзя; заметка без описания сохраняется и отображается без пустого блока.

### ТР-4. Заметка-список (чек-лист)

- Заметка может содержать список пунктов (как «Рекомендательная система» или «Дела по дому»).
- Слева от каждого пункта есть чекбокс; нажатие на него **зачёркивает** пункт и отмечает его выполненным, повторное нажатие возвращает пункт.
- Выполненные пункты сворачиваются в отдельный блок «N выполнено» под невыполненными.
- Пункты можно добавлять, редактировать, удалять и менять местами.
- Список и описание могут быть в одной заметке одновременно.

**Критерий приёмки:** нажатие на чекбокс зачёркивает конкретный пункт, не затрагивая остальные, и состояние синхронизируется между устройствами.

### ТР-5. Ярлыки и цвет заметки

- На заметку можно повесить один или несколько ярлыков.
- Ярлык отображается на карточке заметки.
- **Цвет карточки зависит от ярлыка**: задачи с разными ярлыками визуально отличаются цветом всей карточки, а не только плашкой ярлыка.
- Если на заметке несколько ярлыков, цвет карточки берётся от **основного** ярлыка (первого в списке или выбранного пользователем).
- Заметки можно отфильтровать по ярлыку.

**Критерий приёмки:** две задачи с разными ярлыками на доске имеют разный цвет фона карточки.

### ТР-6. Пользовательские ярлыки

- Пользователь может создавать свои ярлыки.
- Для ярлыка задаются **название** и **цвет** (из палитры или произвольный).
- Ярлык можно переименовать, перекрасить и удалить. При удалении ярлык снимается со всех заметок, сами заметки остаются.
- Изменение цвета ярлыка сразу меняет цвет всех заметок с этим ярлыком.

**Критерий приёмки:** созданный ярлык «Яна Англ» с выбранным цветом доступен при редактировании любой заметки, а карточки с ним окрашены в этот цвет.

### ТР-7. Работа с разных устройств

- Сервис доступен **с ноутбука и с телефона**. Поддерживаемые платформы:

  | Платформа | Устройство |
  |---|---|
  | Windows | ноутбук / ПК |
  | macOS | ноутбук / ПК |
  | iOS | iPhone |

- Заметку можно создать, отредактировать, перенести и архивировать с любого устройства.
- Изменения синхронизируются между устройствами автоматически, без ручного обновления данных.
- Интерфейс адаптирован под узкий экран телефона: столбцы срочности на телефоне листаются горизонтально или переключаются вкладками.

**Критерий приёмки:** заметка, добавленная с телефона, появляется на ноутбуке в том же столбце с тем же ярлыком.

### ТР-8. Архив

- Выполненную задачу можно отправить в **архив** одним действием.
- Архивные заметки не отображаются на основной доске и в закрепе.
- Есть отдельный раздел «Архив» с возможностью просмотра и **восстановления** заметки (она возвращается в свой прежний столбец).
- Архивацию можно применять и к временным, и к постоянным заметкам.

**Критерий приёмки:** после архивации заметка пропадает с доски, видна в разделе «Архив» и восстанавливается обратно.

### ТР-9. Общие (парные) заметки

- Заметку можно сделать **общей** с другим пользователем (например, девушкой), указав его аккаунт.
- Оба пользователя видят заметку **со своих аккаунтов** и могут независимо её редактировать: менять название, описание, пункты списка, отмечать выполненное.
- Изменения одного пользователя видны второму без ручной пересылки.
- На карточке общей заметки есть отметка, что она общая (например, аватар второго участника, как в Google Keep).
- Владелец может прекратить совместный доступ.

**Видимость заметок:**
- Другие пользователи видят **только общие** заметки.
- Все остальные заметки, временные и постоянные, видит только их создатель.

**Ярлыки на общей заметке:**
- На общей заметке действуют **ярлыки создателя**.
- Второй участник видит ярлык, только если у него есть свой ярлык с таким же названием.
- Если такого ярлыка у второго участника нет или цвет ярлыка у него уже занят другим ярлыком, ярлык ему не показывается. Вместо этого предлагается создать такой же ярлык, а при занятом цвете — выбрать другой цвет.
- Пока ярлык у второго участника не создан, карточка отображается у него цветом по умолчанию.

**Критерии приёмки:**
- Пункт, отмеченный выполненным с аккаунта одного пользователя, отображается зачёркнутым у второго.
- Заметка, которой не поделились, не видна никому, кроме создателя.
- Если у второго участника нет ярлыка создателя, он видит заметку без этого ярлыка и предложение создать такой же.

### ТР-10. Статистика и выгрузка архива

**Статистика** (раздел «Статистика» в приложении) по заметкам, отправленным в архив за выбранный период (неделя, месяц, свой период):
- количество заметок по каждому ярлыку и отдельно «Без ярлыка»;
- количество по уровню срочности (Критично, Срочно, Не срочно, Без дедлайна);
- среднее время от создания заметки до отправки в архив, в том числе по срочности;
- количество закрытых задач по неделям.

Правила подсчёта:
- заметка с несколькими ярлыками учитывается в каждом из них, поэтому сумма по ярлыкам может быть больше общего числа (это подписано на странице);
- срочность берётся на момент архивации;
- удалённые навсегда заметки и удалённые ярлыки в статистику не попадают; переименованный ярлык учитывается под новым названием;
- можно смотреть свои, общие или все заметки.

**Выгрузка архива** за выбранный период (по дате архивации):
- файл Markdown (.md) с названием, описанием, пунктами списка (выполненные и нет), ярлыками, срочностью, датами создания и архивации — удобно передать нейросети;
- кнопка «Скопировать» — тот же текст в буфер обмена;
- на iPhone — системное меню «Поделиться».

Автоматическая очистка архива не нужна: при объёме около 1 КБ на заметку бесплатного лимита базы (500 МБ) хватит на десятилетия, а очистка лишила бы статистику и выгрузку данных.

**Критерии приёмки:**
- Для архивных заметок за выбранный месяц видно количество по каждому ярлыку и по каждому уровню срочности.
- Выгрузка за период содержит все архивные заметки этого периода и ни одной лишней.

## 5. Нефункциональные требования

| Требование | Описание |
|---|---|
| Синхронизация | Изменения появляются на других устройствах и у второго пользователя в течение нескольких секунд |
| Совместное редактирование | Одновременные правки двух пользователей не теряют данные друг друга |
| Авторизация | Вход через личный аккаунт; каждый пользователь видит только свои и общие с ним заметки |
| Тема | Тёмная тема, как в текущем Google Keep |
| Скорость работы | Добавление задачи занимает не больше пары действий: название, при необходимости столбец и ярлык |
