# Task-менеджер: требования

## 1. Контекст

Сейчас задачи ведутся в **Google Keep**. Используются два вида заметок.

### 1.1. Постоянные заметки (закреплённые)

Долгоживущие списки, которые периодически пополняются новыми пунктами. Выполненные пункты зачёркиваются и сворачиваются в блок «N выполнено». Эти заметки редактируются **совместно с девушкой**: каждый со своего аккаунта.

Примеры:

| Заметка | Содержимое |
|---|---|
| Дела по дому | Ремонт колеса; выполнено: запустить стиралку, помыть плиту, пропылесосить… (16 шт.) |
| Магазин | Йогурт, яйца, терияки, пергамент, перец… (84 выполнено) |
| Купить | Фильтры, плинтус, подрозетники, клей плиточный, герметик… (94 выполнено) |

### 1.2. Временные заметки (разовые задачи)

Задачи, которые выполняются один раз в течение недели: дела, связанные с учениками, мелкие бытовые задачи, университетские задания. После выполнения заметка отправляется в архив. Для классификации используются ярлыки (например, «ДЗ», «Срочно», «Яна Англ»).

Примеры:

| Заметка | Тип | Содержимое |
|---|---|---|
| Тестирование Лаб 5 | текст | «До 5 ноября», ярлыки «ДЗ», «Срочно» |
| Яна англ дз | текст | ярлык «Яна Англ» |
| Рекомендательная система | список | Поднять Docker на сервере; проверить защиту персональных данных; 6 выполнено |
| Купить снуп | текст | только заголовок |
| Что нужно купить для Ариши | список + ссылки | Охлаждающий гель, подключить увлажнитель; ссылки на goldapple.ru, ozon.ru |
| Изменения резюме | текст | Первые 2 слайда убрать; опыт передвинуть наверх; о себе в конец |

## 2. Проблема

1. Все временные задачи лежат в одной общей куче, их нельзя упорядочить по **срочности и важности**.
2. Ярлык «Срочно» есть, но он не меняет положение заметки и не даёт наглядной картины, что делать в первую очередь.
3. Хочется, чтобы постоянные заметки жили отдельно (в закрепе), а временные раскладывались по **столбцам срочности** слева направо, как на канбан-доске.

## 3. Термины

| Термин | Значение |
|---|---|
| Постоянная заметка | Долгоживущий список, закреплён вверху, не распределяется по срочности |
| Временная заметка | Разовая задача; после выполнения уходит в архив |
| Столбец срочности | Колонка на доске временных задач: Критично / Срочно / Не срочно / Без дедлайна |
| Ярлык | Пользовательская метка с названием и цветом для классификации задач |
| Общая (парная) заметка | Заметка, доступная двум пользователям на чтение и редактирование |
| Связанные задачи (блок) | Несколько временных задач из одного столбца срочности, объединённые в общую обводку; переносятся между столбцами вместе |
| Спринт | Личная группа временных задач из любых столбцов срочности с иконкой-фигурой и порядковыми номерами задач |
| Банка воспоминаний | Общий для пары раздел, не связанный с задачами: нарисованная банка, в которой лежат сердечки-воспоминания |
| Воспоминание (сердечко) | Короткая запись (1–2 предложения) с датой и необязательным названием; в банке показывается сердечком с датой |

## 4. Функциональные требования

### ТР-1. Разделение на постоянные и временные задачи

- При создании заметки выбирается её тип: **постоянная** или **временная**.
- Тип можно изменить у существующей заметки.
- Постоянные заметки выводятся отдельным блоком **«Закреплённые»** в верхней части экрана.
- Временные заметки выводятся ниже, на доске со столбцами срочности (см. ТР-2).

**Критерий приёмки:** постоянная заметка никогда не попадает в столбцы срочности, а временная не попадает в блок закреплённых.

### ТР-2. Столбцы срочности для временных задач

- Временные задачи распределяются по четырём столбцам, расположенным **слева направо в порядке убывания срочности**:

  | № | Столбец |
  |---|---|
  | 1 | Критично |
  | 2 | Срочно |
  | 3 | Не срочно |
  | 4 | Без дедлайна |

- Задачу можно перенести между столбцами (перетаскиванием на ноутбуке; перетаскиванием или выбором из меню на телефоне).
- При создании временной задачи можно сразу выбрать столбец; по умолчанию задача попадает в «Без дедлайна».
- Внутри столбца порядок задач можно менять вручную.

**Критерий приёмки:** на экране четыре столбца в указанном порядке; задача после переноса сохраняет новый столбец и на другом устройстве.

### ТР-3. Название и описание

- У каждой заметки есть **обязательное** поле «Название».
- Поле «Описание» **необязательное**: свободный текст (например, «До 5 ноября», «Первые 2 слайда убрать»).

**Критерий приёмки:** заметку без названия сохранить нельзя; заметка без описания сохраняется и отображается без пустого блока.

### ТР-4. Заметка-список (чек-лист)

- Заметка может содержать список пунктов (как «Рекомендательная система» или «Дела по дому»).
- Слева от каждого пункта есть чекбокс; нажатие на него **зачёркивает** пункт и отмечает его выполненным, повторное нажатие возвращает пункт.
- Выполненные пункты сворачиваются в отдельный блок «N выполнено» под невыполненными.
- Пункты можно добавлять, редактировать, удалять и менять местами.
- Список и описание могут быть в одной заметке одновременно.

**Критерий приёмки:** нажатие на чекбокс зачёркивает конкретный пункт, не затрагивая остальные, и состояние синхронизируется между устройствами.

### ТР-5. Ярлыки и цвет заметки

- На заметку можно повесить один или несколько ярлыков.
- Ярлык отображается на карточке заметки.
- **Цвет карточки зависит от ярлыка**: задачи с разными ярлыками визуально отличаются цветом всей карточки, а не только плашкой ярлыка.
- Если на заметке несколько ярлыков, цвет карточки берётся от **основного** ярлыка (первого в списке или выбранного пользователем).
- Заметки можно отфильтровать по ярлыку.

**Критерий приёмки:** две задачи с разными ярлыками на доске имеют разный цвет фона карточки.

### ТР-6. Пользовательские ярлыки

- Пользователь может создавать свои ярлыки.
- Для ярлыка задаются **название** и **цвет** (из палитры или произвольный).
- Ярлык можно переименовать, перекрасить и удалить. При удалении ярлык снимается со всех заметок, сами заметки остаются.
- Изменение цвета ярлыка сразу меняет цвет всех заметок с этим ярлыком.

**Критерий приёмки:** созданный ярлык «Яна Англ» с выбранным цветом доступен при редактировании любой заметки, а карточки с ним окрашены в этот цвет.

### ТР-7. Работа с разных устройств

- Сервис доступен **с ноутбука и с телефона**. Поддерживаемые платформы:

  | Платформа | Устройство |
  |---|---|
  | Windows | ноутбук / ПК |
  | macOS | ноутбук / ПК |
  | iOS | iPhone |

- Заметку можно создать, отредактировать, перенести и архивировать с любого устройства.
- Изменения синхронизируются между устройствами автоматически, без ручного обновления данных.
- Интерфейс адаптирован под узкий экран телефона: столбцы срочности на телефоне листаются горизонтально или переключаются вкладками.

**Критерий приёмки:** заметка, добавленная с телефона, появляется на ноутбуке в том же столбце с тем же ярлыком.

### ТР-8. Архив

- Выполненную задачу можно отправить в **архив** одним действием.
- Архивные заметки не отображаются на основной доске и в закрепе.
- Есть отдельный раздел «Архив» с возможностью просмотра и **восстановления** заметки (она возвращается в свой прежний столбец).
- Архивацию можно применять и к временным, и к постоянным заметкам.

**Критерий приёмки:** после архивации заметка пропадает с доски, видна в разделе «Архив» и восстанавливается обратно.

### ТР-9. Общие (парные) заметки

- Заметку можно сделать **общей** с другим пользователем (например, девушкой), указав его аккаунт.
- Оба пользователя видят заметку **со своих аккаунтов** и могут независимо её редактировать: менять название, описание, пункты списка, отмечать выполненное.
- Изменения одного пользователя видны второму без ручной пересылки.
- На карточке общей заметки есть отметка, что она общая (например, аватар второго участника, как в Google Keep).
- Владелец может прекратить совместный доступ.

**Что общее, а что у каждого своё:**
- Название, описание, пункты списка, ярлыки создателя и тип заметки (постоянная/временная) — общие.
- **Постоянная (закреплённая) заметка общая целиком**, включая архив: отправил в архив один — заметка в архиве у обоих.
- **У временной задачи у каждого участника своё место**: свой столбец срочности, свой порядок в столбце и свой архив. Новый участник начинает со столбца владельца.
- «Удалить навсегда»: владелец удаляет заметку у всех, участник — только у себя (выходит из заметки).

**Видимость заметок:**
- Другие пользователи видят **только общие** заметки.
- Все остальные заметки, временные и постоянные, видит только их создатель.

**Ярлыки на общей заметке:**
- На общей заметке действуют **ярлыки создателя**.
- Второй участник видит ярлык, только если у него есть свой ярлык с таким же названием.
- Если такого ярлыка у второго участника нет или цвет ярлыка у него уже занят другим ярлыком, ярлык ему не показывается. Вместо этого предлагается создать такой же ярлык, а при занятом цвете — выбрать другой цвет.
- Пока ярлык у второго участника не создан, карточка отображается у него цветом по умолчанию.

**Критерии приёмки:**
- Пункт, отмеченный выполненным с аккаунта одного пользователя, отображается зачёркнутым у второго.
- Заметка, которой не поделились, не видна никому, кроме создателя.
- Если у второго участника нет ярлыка создателя, он видит заметку без этого ярлыка и предложение создать такой же.

### ТР-10. Статистика и выгрузка архива

**Статистика** (раздел «Статистика» в приложении) по заметкам, отправленным в архив за выбранный период (неделя, месяц, свой период):
- количество заметок по каждому ярлыку и отдельно «Без ярлыка»;
- количество по уровню срочности (Критично, Срочно, Не срочно, Без дедлайна);
- среднее время от создания заметки до отправки в архив, в том числе по срочности;
- количество закрытых задач по неделям.

Правила подсчёта:
- заметка с несколькими ярлыками учитывается в каждом из них, поэтому сумма по ярлыкам может быть больше общего числа (это подписано на странице);
- срочность берётся на момент архивации;
- удалённые навсегда заметки и удалённые ярлыки в статистику не попадают; переименованный ярлык учитывается под новым названием;
- можно смотреть свои, общие или все заметки.

**Выгрузка архива** за выбранный период (по дате архивации):
- файл Markdown (.md) с названием, описанием, пунктами списка (выполненные и нет), ярлыками, срочностью, датами создания и архивации — удобно передать нейросети;
- кнопка «Скопировать» — тот же текст в буфер обмена;
- на iPhone — системное меню «Поделиться».

Автоматическая очистка архива не нужна: при объёме около 1 КБ на заметку бесплатного лимита базы (500 МБ) хватит на десятилетия, а очистка лишила бы статистику и выгрузку данных.

**Критерии приёмки:**
- Для архивных заметок за выбранный месяц видно количество по каждому ярлыку и по каждому уровню срочности.
- Выгрузка за период содержит все архивные заметки этого периода и ни одной лишней.

### ТР-11. Связанные задачи

Временные задачи, которые относятся к одному делу (например, несколько шагов «Составить резюме»), можно связать между собой. Связанные задачи образуют **блок**: на доске они стоят подряд и обведены общей рамкой.

**Как связать и отвязать:**
- в настройках существующей временной задачи или при создании новой открывается выпадающий список задач **из того же столбца срочности**; можно выбрать сразу несколько;
- связать можно только с действующими задачами на доске (не с архивными);
- задача состоит не больше чем в одном блоке: если выбрать задачу, которая уже в блоке, текущая задача вступает в этот блок (выбранные блоки объединяются);
- в настройках задачи есть кнопка **«Отвязать»**; если в блоке осталась одна задача, рамка пропадает;
- число задач в блоке не ограничено;
- постоянные заметки не связываются; если связанную задачу сделать постоянной, она выходит из блока.

**Связи личные:** как и столбец с порядком (ТР-9), связи у каждого пользователя свои. Второй участник общей задачи не видит ваших связей; общую задачу можно связать со своей необщей.

**Правила на доске:**
1. Связать можно только задачи из **одного столбца срочности**.
2. Если перетащить одну задачу блока в другой столбец (или выбрать другой столбец в меню на телефоне), **весь блок** переезжает в этот столбец.
3. Задачи блока всегда стоят **друг под другом**. Если в момент связывания между ними были другие задачи, задачи блока собираются на месте верхней из них, а остальные задачи столбца сохраняют свой порядок.
4. Порядок задач внутри блока можно менять перетаскиванием. Если перетащить задачу блока за его пределы в том же столбце, переезжает весь блок. Чужую задачу нельзя бросить в середину блока: она встаёт перед ним.
5. **Ярлыки блока:** ярлык, поставленный на одну задачу блока, сразу ставится на все задачи блока; снятый — снимается у всех. Основной ярлык (цвет карточки) у каждой задачи свой. На чужой общей задаче ярлыки ставит её создатель (ТР-9), поэтому её ярлыки не меняются. При связывании ярлыки задач не объединяются.
6. При отправке задачи в архив она **выходит из блока на доске**, остальные задачи блока остаются связанными.
7. Восстановленная из архива задача возвращается **в конец своего блока** (и в его столбец), если на доске от блока что-то осталось.

**Архив и выгрузка:**
8. В архиве связанные задачи тоже показываются объединёнными в блок; блок стоит по дате последней архивации своих задач. В выгрузке .md у связанной задачи указано, с какими задачами она связана; в выгрузку за период попадают только задачи этого периода.

**Статистика:**
9. В статистике есть отдельный раздел про связанные задачи за период:
   - сколько задач закрыто в составе блоков и сколько одиночных;
   - сколько блоков закрыто полностью (все задачи в архиве, последняя — в этом периоде);
   - средний размер закрытого блока;
   - среднее время от создания первой задачи блока до архивации последней.

   В общих показателях (по ярлыкам, срочности, времени до архива, по неделям) каждая задача блока учитывается **как отдельная**.

Позже появится второй способ связывания задач, его требования будут описаны отдельно.

**Критерии приёмки:**
- Две задачи из одного столбца после связывания стоят подряд в общей рамке; задачу из другого столбца связать нельзя.
- После переноса одной задачи блока в другой столбец все задачи блока оказываются в новом столбце, в том же порядке, и так же отображаются на другом устройстве.
- После архивации одной задачи блока остальные остаются в рамке на доске, а архивная задача видна в архиве в блоке со своими связанными задачами.
- В выгрузке .md у связанных задач есть пометка о связи.
- Ярлык, поставленный на одну задачу блока, появляется на всех задачах блока.

### ТР-12. Спринты

Спринт объединяет временные задачи **из разных столбцов срочности** под одной целью (например, «Сессия» или «Переезд»). В отличие от блока (ТР-11), задачи спринта на доске не двигаются: каждая остаётся в своём столбце, а на её карточке появляется значок спринта с номером.

**Вкладка «Спринты»:**
- в шапке приложения есть вкладка «Спринты»;
- у спринта есть **название** (обязательно), **описание** (необязательно), **дата окончания** (необязательно) и **иконка**;
- на вкладке видны действующие спринты: иконка, название, описание, дата окончания и задачи спринта по порядку номеров;
- название, описание, дату окончания и иконку действующего спринта можно изменить;
- порядок задач в спринте меняется перетаскиванием на вкладке «Спринты», номера при этом пересчитываются;
- задачу можно убрать из спринта и на вкладке, и в окне задачи.

**Иконки:**
- иконка — простая фигура без своего цвета: круг, квадрат, треугольник, ромб, шестиугольник, звезда, сердце, щит;
- одна фигура принадлежит **не больше чем одному действующему** спринту; занятые фигуры при выборе недоступны;
- когда спринт завершён или удалён, его фигура снова становится доступной.

**Задача и спринт:**
- в спринт входят только **временные** задачи; задача состоит не больше чем в одном спринте; если задачу сделать постоянной, она выходит из спринта;
- при создании задачи и в окне существующей задачи можно выбрать действующий спринт и **номер** задачи в нём;
- номера всегда идут подряд 1, 2, 3… без пропусков; по умолчанию задача встаёт в конец спринта; выбранный номер ставит задачу на это место, остальные задачи сдвигаются;
- в окне задачи видно, к какому спринту она относится (иконка и название);
- на карточке задачи на доске показывается **иконка спринта с номером задачи внутри**. Она стоит справа в нижней строке карточки: на уровне дедлайна; если дедлайна нет — на уровне ярлыков; если нет и ярлыков — в правом нижнем углу (верхний правый угол занят кнопкой «В архив»);
- **на ноутбуке** нажатие на иконку спринта открывает окно спринта для быстрого просмотра: иконка, название, дата окончания, описание и задачи по номерам (задача, с которой открыли окно, выделена); оттуда можно перейти на вкладку «Спринты». **На телефоне** иконка не нажимается — касание открывает саму задачу, чтобы не открыть спринт случайно при прокрутке;
- задача, отправленная в архив, **остаётся в спринте**: на вкладке «Спринты» она показана выполненной (зачёркнутой) со своим номером, номера остальных не меняются; восстановленная из архива задача остаётся на своём месте в спринте;
- задача, удалённая навсегда, выходит из спринта, номера оставшихся сдвигаются.

**Завершение и архив спринтов:**
- действующий спринт можно пометить **выполненным**: он уходит в архив спринтов и больше не предлагается при выборе спринта в задаче;
- невыполненные задачи завершённого спринта **остаются на доске** в своих столбцах, но без значка спринта; в архиве спринта они отмечены как невыполненные;
- такую задачу можно добавить в другой действующий спринт: она переходит туда и в архиве прежнего спринта больше не показывается;
- архив спринтов находится на вкладке «Спринты»: у каждого спринта видны задачи с отметкой «выполнено / не выполнено» и дата завершения;
- завершённый спринт можно **вернуть** в действующие, если его фигура свободна (если занята — при возврате выбирается другая); задачи, которые ещё на доске, снова получают его значок;
- спринт можно **удалить** навсегда; задачи при этом не удаляются, а только выходят из спринта.

**Спринты личные:** как столбец, порядок и связи (ТР-9, ТР-11), спринты у каждого пользователя свои. В свой спринт можно добавить общую задачу; второй участник не видит ваш спринт и значок на карточке.

**Связь с блоками (ТР-11):** спринт и блок независимы: задачи одного блока могут быть в разных спринтах или вне спринта.

**Ярлыки спринта:**
- ярлык, **поставленный** на одну задачу спринта (в окне задачи или при создании задачи в спринте), сразу ставится на все задачи этого спринта, которые сейчас на доске;
- **снятый** ярлык снимается только с самой задачи (и с её блока по правилу ТР-11), у остальных задач спринта он остаётся;
- архивные задачи спринта ярлык не получают; у завершённого спринта правило не действует;
- если задача спринта состоит в блоке, ярлык получает и весь её блок (ТР-11), а дальше — и спринты задач этого блока;
- на чужой общей задаче ярлыки ставит её создатель (ТР-9), поэтому её ярлыки не меняются;
- при добавлении задачи в спринт ярлыки задач не объединяются.

**Критерии приёмки:**
- Задачи из столбцов «Критично» и «Не срочно», добавленные в один спринт, показывают на карточках одну и ту же фигуру с номерами 1 и 2; на другом устройстве так же.
- После перетаскивания задачи на вкладке «Спринты» номера на карточках доски меняются.
- Занятую фигуру нельзя выбрать для второго действующего спринта; после завершения спринта она снова доступна.
- Завершённый спринт не предлагается в окне задачи, а значок пропадает с карточек его невыполненных задач.
- Ярлык, поставленный на одну задачу действующего спринта, появляется на всех его задачах на доске.

### ТР-13. Банка воспоминаний

Отдельный раздел, **никак не связанный с задачами**: в нём пара хранит общие тёплые воспоминания «в милой обёртке». Каждое воспоминание — сердечко в нарисованной банке; на сердечке написана дата. Ярлыки, срочность, архив, статистика и выгрузка на банку не распространяются.

**Вкладка «Банка»:**
- в шапке приложения есть вкладка «Банка» (маршрут `/jar`), рядом с остальными вкладками;
- вкладка оформлена в **отдельном светлом (белом) стиле**, независимо от тёмной темы остального приложения: белый или почти белый фон страницы, светлые окна и кнопки в розовых тонах; шапка приложения остаётся как есть;
- в центре вкладки — нарисованная банка, **максимально похожая на референс** (фото 1 к требованию):
  - банка в **белых и розовых тонах**: почти белое стекло с лёгким розоватым отливом, контур тёмно-сливового цвета, нарисованный «от руки» (неровная толщина линии, скруглённые углы);
  - пропорции референса: высокая банка с округлыми «плечами» и закруглённым дном, узкое горлышко, крышка чуть шире горлышка;
  - **светло-розовая крышка** с вертикальными полосками-рифлением и тонкой светлой полоской-бликом сверху;
  - белый блик на стекле вдоль левой стенки и светлая полоска у дна;
  - по бокам банки — по три коротких штриха «сияния» тёмно-сливового цвета;
  - сердечки — **розовые, пухлые, глянцевые**, с тёмным контуром и белым бликом в левой верхней части, плотно уложены и повёрнуты в разные стороны, как на референсе;
- рисунок собственный (SVG), повторяющий стиль и композицию референса; сама картинка со стока (с водяными знаками) в приложение не копируется;
- банка помещается на экран телефона без прокрутки вместе с кнопками под ней;
- под банкой кнопки **«Добавить воспоминание»** и **«Встряхнуть»**; рядом счётчик «В банке N воспоминаний».

**Общая банка на пару:**
- у пользователя не больше одной банки; банка общая для двух человек;
- при первом заходе на вкладку пользователь видит пустую банку и может начать пользоваться ей сразу (банка создаётся автоматически, он — её владелец);
- владелец приглашает второго участника **по email**, как в общих заметках (ТР-9): второй должен хотя бы раз войти в приложение. Если у приглашённого уже есть своя банка с воспоминаниями, приглашение не проходит с понятным сообщением (слияние банок — вне требований); пустая банка приглашённого удаляется;
- в банке не больше двух участников; оба видят все воспоминания и оба могут добавлять новые;
- участник может выйти из банки, владелец — закрыть доступ второму; воспоминания вышедшего остаются в банке.

**Добавление воспоминания:**
- кнопка «Добавить воспоминание» открывает окно с полями:
  - **название** — необязательно, до 40 символов;
  - **текст** — обязательно, 1–2 предложения, до 280 символов, со счётчиком оставшихся символов;
  - **дата** — обязательно, по умолчанию сегодня; можно выбрать прошедшую дату, будущую нельзя;
- кнопка «Положить в банку» неактивна, пока текст пустой; закрытие окна без отправки ничего не сохраняет;
- после отправки окно закрывается, и новое сердечко **падает сверху в банку** (анимация с лёгким отскоком) и ложится к остальным;
- если второй участник в это время открыл банку, новое сердечко появляется у него тоже — с той же анимацией падения (синхронизация в реальном времени, ТР-7).

**Сердечко в банке:**
- на сердечке написана дата воспоминания в формате «ДД.ММ» (год — в окне воспоминания);
- **цвет сердечка зависит от автора**: два хорошо различимых оттенка розового в гамме референса (например, нежно-розовый и более насыщенный розовый) (у владельца банки — один, у второго участника — другой); в окне воспоминания указан автор;
- сердечки лежат в банке «кучей»: плотно, с небольшими поворотами, снизу вверх, не вылезая за стенки;
- нажатие на сердечко открывает **окно воспоминания**.

**30 сердечек в банке:**
- в банке одновременно рисуется **не больше 30 сердечек**; если воспоминаний 30 или меньше — видны все;
- если больше — показываются **30 случайных**, набор **меняется раз в сутки** (в полночь по местному времени) и одинаков в течение дня при любом заходе и на любом устройстве;
- воспоминания, **добавленные сегодня**, всегда попадают в банку (вытесняя случайные), чтобы только что добавленное сердечко было видно;
- остальные воспоминания доступны через список под крышкой и через «Встряхнуть».

**Окно воспоминания:**
- показывает название (если есть), полную дату («6 ноября 2026»), текст, автора (имя и аватар);
- **автор** может изменить название, текст и дату или удалить воспоминание (с подтверждением); у второго участника этих кнопок нет;
- при изменении даты на сердечке меняется дата; при удалении сердечко исчезает из банки (на освободившееся место в тот же день новое случайное не подставляется — до следующей смены набора).

**Список под крышкой:**
- нажатие на **крышку банки** открывает окно со списком **всех** воспоминаний (не только 30 видимых);
- список отсортирован по дате воспоминания, новые сверху, с разделителями по месяцам («Ноябрь 2026»);
- в строке: маленькое сердечко цвета автора, дата, название или начало текста;
- нажатие на строку открывает окно воспоминания; закрыв его, возвращаемся к списку.

**Встряхнуть:**
- кнопка «Встряхнуть» запускает анимацию покачивания банки, после которой открывается окно **случайного** воспоминания из всех (не только из видимых 30);
- то же воспоминание не выпадает два раза подряд, если в банке больше одного воспоминания;
- в пустой банке кнопка неактивна.

**Пустая банка:** если воспоминаний нет, банка пустая, под ней подсказка «Положите первое воспоминание».

**Анимации:** падение сердечка и покачивание банки отключаются, если в системе включено «Уменьшение движения» (`prefers-reduced-motion`): сердечко просто появляется, случайное воспоминание открывается сразу.

**Критерии приёмки:**
- Воспоминание, добавленное с телефона, сразу падает сердечком с датой в банку, и через несколько секунд то же сердечко появляется в банке у второго участника.
- Сердечки двух участников разного оттенка; в окне воспоминания виден автор.
- Вкладка «Банка» светлая (белый фон, розовые акценты) при тёмной теме остального приложения; банка по форме, крышке, контуру, бликам, штрихам сияния и сердечкам узнаваемо повторяет референс.
- Второй участник не может изменить или удалить чужое воспоминание ни в интерфейсе, ни запросом к базе в обход интерфейса (RLS).
- При 40 воспоминаниях в банке ровно 30 сердечек, набор не меняется при повторном заходе в тот же день и одинаков на ноутбуке и телефоне; в списке под крышкой — все 40.
- «Встряхнуть» открывает воспоминание, которого может не быть среди видимых сердечек.
- Пользователь, не состоящий в банке, не видит её воспоминаний.

## 5. Нефункциональные требования

| Требование | Описание |
|---|---|
| Синхронизация | Изменения появляются на других устройствах и у второго пользователя в течение нескольких секунд |
| Совместное редактирование | Одновременные правки двух пользователей не теряют данные друг друга |
| Авторизация | Вход через личный аккаунт; каждый пользователь видит только свои и общие с ним заметки |
| Тема | Тёмная тема, как в текущем Google Keep |
| Скорость работы | Добавление задачи занимает не больше пары действий: название, при необходимости столбец и ярлык |
